# 5–10 Minute Demonstration Script

Use only the synthetic files in `Input_Data/`. Start from an empty project so the ingestion can be shown from the beginning
(`Documentation/RUN_AND_DEPLOY.md` describes how to start API, worker and frontend). The screenshots in
`Evaluation_Results/Screenshots/` show the expected result of every step.

## 0:00–0:45 — Problem and guard-rails

Introduce the AUTOSAR Architecture Intelligence Assistant. It turns HLD documents into an evidence-linked knowledge graph and
answers engineering questions with citations. Three rules to state: every fact points to its source passage; AI-extracted
facts stay **PENDING** until a human verifies, corrects or rejects them; findings say *"Potential inconsistency detected"*,
never *"the architecture is wrong"*.

## 0:45–2:30 — Ingestion (Documents screen)

Show `Input_Data/BrakeController_HLD_v1.md` and `ABS_Subsystem_HLD.md`. Add both files at once. Point out:

* the **upload queue**: only one document is processed at a time, the other waits;
* the **five-stage tracker** (Parse & structure → Embed passages → Extract entities → Resolve duplicates → Build graph):
  each stage animates and is ticked when its job completes;
* safe handling: file validation, SHA-256 content hash, managed storage, project isolation.

Then upload `BrakeController_HLD_v2.md` as `BrakeController_HLD.md` and show it appearing as **Version 2** of the same document.

## 2:30–3:30 — What was stored (terminal, optional but recommended)

In `psql`, show `\d chunks` (`vector(768)`, HNSW and GIN indexes), the section/chunk hierarchy with breadcrumbs, and the
provenance query that joins relationship → evidence → chunk → section → document version
(`Evaluation_Results/Screenshots/psql/`).

## 3:30–5:15 — Ask Architecture

Ask, in this order:

1. *"What does BrakeController require?"* (Hybrid) — claims with citation markers, the graph fact with
   *Confidence 1.00 · EXPLICIT · PENDING*, expandable source excerpts, limitations.
2. *"Which DID corresponds to the vehicle speed signal and what is its data length?"* (Source only) — a table-row answer.
3. *"What is the maximum supported braking torque of the BrakeController in newton-metres?"* — the system answers
   **Insufficient evidence** instead of inventing a number.

## 5:15–6:15 — Knowledge graph and human review

Open the graph. Click a node and a relationship: show the evidence passages, confidence, extraction type and validation
history. **Verify** one relationship, **reject** one generic entity with a reason, **edit** one entity; the node colours change
(green / red) and the text status changes with them. Show the Review Queue and that the original extraction is kept.

## 6:15–7:15 — Impact analysis and findings

Select `WheelSpeedInterface`, 2 hops: direct and indirect impacts, each with the connecting path and the weakest link's status.
Open **Findings**: *"Potential inconsistency detected: interface 'VehicleStateInterface' has no provider relationship."*

## 7:15–8:15 — Revision comparison and evaluation

Compare Version 1 → Version 2: document, section, entity and relationship changes (added / removed / renamed / target
changed), each with its source passage. Show `Evaluation_Results/EVALUATION_RESULTS.md` (retrieval evaluation) and the
automated test results.

## 8:15–9:00 — Configuration and limitations

State the providers (Groq `openai/gpt-oss-120b`, Gemini `gemini-embedding-2`), the declared hosted-API dependency and the
provider abstraction (local Ollama is supported but was not used for the demonstration). Summarise the limitations from the
Technical Report honestly: small synthetic corpus, rule-based question planner, no live OCR run, accuracy not measured on
real HLDs.

## Recording checklist

- Use synthetic data only unless written approval exists.
- Make citations and provenance visible in at least one answer.
- Record only from the submitted source snapshot and configuration.
